### Cross-cutting observations

- **Trust boundaries are correctly placed**: payload validation at the SW dispatcher (`storage-handlers.js:786,791,797,821`), payload re-validation inside the orchestrator (`chrome-sync.js:226-228`), allow-list write validation (`groups.js:108-146`), shape re-validation on every read (`shapes.js:144-157`). Defense in depth at every layer.
- **PII discipline**: the toast copy contains only numeric counts; bookmark URLs and titles never enter the chrome-sync code path's UI surface. The new module's only `url` reference (`chrome-sync.js:141,156`) is the join key used for tab-to-item matching, never logged or rendered.
- **MV3 SW cold-start**: `chrome-sync.js` makes no assumption about in-memory state — `_collectWindowState` reads fresh from `chrome.tabs.query` and `listGroups()/listItems()` on every call. Service-worker suspend mid-flight would lose the in-flight `_isSyncing` flag, but since SW suspension implies the sync is dead anyway, this is correct.
- **Extension page CSP**: settings.html does not load any external script; the existing strict `script-src 'self'` CSP is preserved. No new inline scripts, no new `<script src="...">` tags pointing at non-self origins.

**Top 3 most-impactful:**

1. **H-1 (aria-busy / in-progress feedback)** — The button disable pattern is correct but incomplete: no `aria-busy`, no text change, no spinner. For a 2-second 50-tab sync, keyboard and screen-reader users receive zero in-flight signal. The CSS hook already exists. Fix is 2–3 lines in `_onSyncClick`.

2. **H-2 (missing tab-gone integration test)** — Spec §8.2 explicitly requires this test by name. The per-tab fallback loop (`chrome-sync.js:253–260`) and `_classifyError` are exercised by zero end-to-end tests. Tab-gone is the most realistic mid-sync failure mode on a live window.

3. **M-2 (toast color-only differentiation, WCAG 1.4.1)** — Three states differentiated by border color only. While screen readers announce text carrying semantic state, sighted low-vision users have no non-color signal. WCAG 1.4.1 is Level A. A text prefix in the message string is a 3-line fix.

**UX pattern to flag for S43 auto-sync planning:** The Settings page has no "last synced at" history. Users cannot tell at a glance whether the Chrome strip matches TJ state without re-triggering sync. When S43 introduces auto-sync, a "Last synced: N minutes ago" status line beneath the button would address both the H-1 in-progress feedback gap and provide continuous-state visibility.
