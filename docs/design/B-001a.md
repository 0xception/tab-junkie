## 1. Edge case rulings (from R1 flags)

- **ULID collision** → impossible-by-construction with strict-monotonic generator. Define `ERR_ID_COLLISION` defensively; expected throw count: zero.
- **Quota warning UX** → B-001b owns it. B-001a only throws `ERR_QUOTA_EXCEEDED` on write failure; stash `bytesInUse` on a non-exported telemetry hook for B-001b to consume.
- **CRUD before SW ready barrier** → reject with `ERR_NOT_READY`. B-001a ships a stubbed module-level `readyPromise = Promise.resolve()`; B-001b replaces it with the migration-gated real promise.

## 7. Error taxonomy

All extend `StorageError` class: `{ code, message, cause? }`.

| Code | When it fires | Caller recovery |
|------|---------------|-----------------|
| `ERR_NOT_READY` | `readyPromise` unresolved or rejected | Show skeleton / safe-mode banner, retry |
| `ERR_NOT_FOUND` | `update`/`delete` with unknown id (`get` returns `null` instead) | Refresh view |
| `ERR_DEPTH_EXCEEDED` | Group parentId would produce depth > 1 | Inline form error |
| `ERR_CIRCULAR_REF` | `updateGroup` sets parentId to self/descendant | Inline form error |
| `ERR_DIRECT_WRITE` | Write from non-SW or foreign sender | Non-recoverable bug; log + throw |
| `ERR_CORRUPT_DATA` | Partition shape validator fails on read | Other partitions still usable; banner (B-001b); offer export-and-reset |
| `ERR_ID_COLLISION` | Defensive — should never fire | Retry create once |
| `ERR_QUOTA_EXCEEDED` | `chrome.storage.local.set` rejects on quota | Prompt user to delete items (B-001b UI) |
| `ERR_VALIDATION` | Missing/wrong-type payload field | Inline form error |
| `ERR_TX_CONFLICT` | Mutator throws synchronously | Automatic rollback (nothing committed) |

## 8. writeTransaction implementation

### Algorithm
```js
// Module-level queue anchor
let txQueue = Promise.resolve();

export function writeTransaction(ops) {
  const run = async () => {
    // 1. Collect unique partition keys
    const keys = [...new Set(ops.map(o => `tj:${o.partition}`))];
    // 2. Single atomic get
    const current = await chrome.storage.local.get(keys);
    // 3. Apply mutators in declared order
    const next = { ...current };
    for (const op of ops) {
      const k = `tj:${op.partition}`;
      try {
        next[k] = op.mutator(next[k] ?? defaultShape(op.partition));
      } catch (e) {
        throw new StorageError('ERR_TX_CONFLICT', e.message, e);
      }
    }
    // 4. Validate post-mutation shapes
    for (const k of keys) assertShape(k, next[k]);
    // 5. Single atomic set
    try {
      await chrome.storage.local.set(next);
    } catch (e) {
      if (isQuotaError(e)) throw new StorageError('ERR_QUOTA_EXCEEDED', e.message, e);
      throw e;
    }
  };
  // Chain; swallow errors for queue continuity only
  const p = txQueue.then(run, run);
  txQueue = p.catch(() => {});
  return p;
}
```

### Guarantees
- **Atomicity:** single `chrome.storage.local.set({k1,k2,k3})` commits all keys or none (Chrome API guarantee).
- **Serialization (AC10):** call N awaits call N-1's `set` resolution before its own `get`.
- **Crash safety:** SW termination between `get` and `set` → nothing written (pre-tx state intact). During `set` → Chrome guarantees fully applied or not applied, never partial.
- **Failure modes:** mutator throw → `ERR_TX_CONFLICT`, nothing committed. `set` reject → typed error bubbles, nothing committed.

All single-partition writes in `items.js`/`groups.js`/`preferences.js` internally route through `writeTransaction`. There is no other write path (AC6).
