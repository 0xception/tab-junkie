## 1. State Model

### New module-level state in `sidepanel.js`

```
let _cachedItems = [];           // Last items array from renderAll / broadcast
let _cachedGroups = [];          // Last groups array from renderAll / broadcast
let _cachedLiveStates = {};      // Last liveStates from renderAll / broadcast
let _cachedDriftRecords = {};    // Last driftRecords from renderAll / broadcast
let _filterQuery = '';           // Current normalized (lowercased, trimmed) query
let _filterTimerId = null;       // setTimeout ID for debounce
```

**Why a cache is needed:** Currently `renderAll()` receives data as arguments and does not store it. The filter must operate on the last-rendered dataset without sending any SW messages (AC9). The cache is populated inside `renderAll()` before DOM work begins — every call to `renderAll` (init, broadcast, form-submit fallback) updates the cache.

**Cache lifecycle:** Panel-lifetime only. No persistence across panel close/open (non-goal). Cleared implicitly when the panel is destroyed.

## 3. Debounce Implementation

Plain `setTimeout` / `clearTimeout` pattern. No library dependency.

**Event flow:**

1. User types in `#filter-input` — fires `input` event
2. Handler: `clearTimeout(_filterTimerId)`
3. Handler: `_filterTimerId = setTimeout(applyFilter, 150)`
4. After 150ms idle: `applyFilter()` executes

**`applyFilter()` sequence:**

1. Read `_filterQuery = filterInputEl.value.trim().toLowerCase()`
2. If query is empty: call `clearFilter()` and return
3. Show/hide the clear button based on query length
4. Walk cached data and apply visibility — see section 6
5. Reset scroll to top (AC10): `itemListEl.scrollTop = 0`

**Why `input` event, not `keyup`:** The `input` event fires on paste, autocomplete, voice input, and IME composition — `keyup` misses some of these. More robust.

## 4. Filter Algorithm

**Simple case-insensitive substring match** using `String.prototype.includes()`.

```
const query = _filterQuery;  // already lowercased + trimmed
const matches = item.title.toLowerCase().includes(query)
             || item.url.toLowerCase().includes(query);
```

**No Fuse.js / fuzzy matching.** B-052 owns fuzzy search. B-021 is a lightweight visibility filter only. This keeps the dependency count at zero and guarantees sub-1ms per item on a 500-item collection.

**Case insensitivity (AC7):** Both query and target strings are lowercased before comparison.

## 5. Match Highlighting Approach

Matched substrings are wrapped in `<mark>` elements. **No `innerHTML` is used** — all rendering is DOM-API only to prevent XSS from untrusted bookmark titles/URLs.

**Helper function: `buildHighlightedText(text, query)`**

1. If `query` is empty or not found in `text.toLowerCase()`: return a single `TextNode` of `text`
2. Find all non-overlapping match positions (case-insensitive scan via `indexOf` loop)
3. Build a `DocumentFragment`:
   - For each unmatched segment: `document.createTextNode(segment)`
   - For each matched segment: create a `<mark>` element, set its `textContent` to the original-case substring
4. Return the fragment

**Usage:** When applying the filter, the `.item-title` and `.item-url` elements inside each visible row have their children replaced with the output of `buildHighlightedText()`.

**When filter is cleared:** Title and URL elements revert to plain `textContent` from cached item data (no `<mark>` tags).

**`<mark>` styling** (added to `sidepanel.css`):

```css
.item-title mark,
.item-url mark {
  background: var(--accent-subtle);
  color: inherit;
  border-radius: 2px;
  padding: 0 1px;
}
```

## 6. DOM Strategy — Hide/Show Existing Rows

**Recommended approach: Option A — hide/show existing rows using the `hidden` attribute.**

**Justification:**

- **Performance on 500 items:** Toggling `hidden` on existing DOM nodes is an O(n) attribute-set operation with zero garbage collection pressure. Re-rendering (Option B) would create ~500 new DOM subtrees per keystroke (after debounce), triggering layout thrash and GC pauses.
- **Preserves DOM identity:** Action button event handlers, favicon `onerror` state, and `data-*` live-state attributes are preserved. A re-render would lose transient DOM state.
- **Scroll position:** AC10 requires resetting scroll to top. With hide/show, we simply set `itemListEl.scrollTop = 0` after toggling visibility.
- **Existing `[hidden] { display: none !important; }` rule** in the CSS already handles hidden elements correctly.

**`applyFilter()` DOM walk:**

1. For each `.item-row` in `#item-list`:
   - Read `row.dataset.itemId`
   - Look up item in a `Map<itemId, Item>` built from `_cachedItems` (built once per cache update, stored as `_itemById`)
   - Test `title.toLowerCase().includes(query) || url.toLowerCase().includes(query)`
   - If match: `row.hidden = false`, apply highlights to `.item-title` and `.item-url`
   - If no match: `row.hidden = true`
2. Apply group visibility (see section 7)
3. Apply empty-state check (see section 8)
4. Reset scroll: `itemListEl.scrollTop = 0`

**When `renderAll` is called while a filter is active:** After `renderAll` rebuilds the DOM from new data, it must re-apply the active filter. Add a check at the end of `renderAll`: if `_filterQuery` is non-empty, call `applyFilter()`.

## 7. Group Visibility During Filter

After item visibility is resolved, iterate each `.group-section` in `#item-list`:

1. Query all `.item-row` descendants that are NOT hidden
2. If zero visible rows: set `section.hidden = true` (hides header + items — AC5)
3. If one or more visible rows: set `section.hidden = false`

**Collapsed groups:** If a group is collapsed (`collapsedGroups` set), its `.group-items` container has `hidden` on it. During filter, the filter must still check items inside collapsed groups. If any match, the group section is shown AND the `.group-items` container is temporarily un-hidden (overriding collapse). When the filter is cleared, the original collapsed state is restored from `collapsedGroups`.

**Implementation detail:** When filter is active, collapsed groups expand to show matches. Track this with a CSS class `.group-section--filter-expanded` or simply force `.group-items[hidden]` visible during active filter. On clear, re-apply collapsed state from `collapsedGroups`.

**Group header count badge:** During filter, update `.group-header-count` to show the visible (matching) item count, not the total. On clear, restore total count.

## 8. Empty-State During Filter

**Separate element for filter-empty-state.** Do NOT reuse `#empty-state` (which means "no bookmarks saved at all").

**New HTML element** (added after `#item-list`, before `#dialog-overlay`):

```html
<div id="filter-empty-state" class="filter-empty-state" hidden>
  <svg class="filter-empty-icon" width="48" height="48" viewBox="0 0 48 48" fill="none" aria-hidden="true">
    <circle cx="20" cy="20" r="14" stroke="currentColor" stroke-width="2"/>
    <path d="M30 30l10 10" stroke="currentColor" stroke-width="2" stroke-linecap="round"/>
    <path d="M14 20h12" stroke="currentColor" stroke-width="2" stroke-linecap="round"/>
  </svg>
  <p class="filter-empty-message">No matching bookmarks</p>
</div>
```

**Show/hide logic:**

- After `applyFilter()` completes, if zero `.item-row` elements are visible AND `_filterQuery` is non-empty: show `#filter-empty-state`, hide `#item-list`
- When filter is cleared or matches exist: hide `#filter-empty-state`, show `#item-list`

**Styling:** Same flex-column centered layout as `.empty-state` but smaller (no CTA button, shorter height).

## 9. Clear (x) Control

**Position:** A `<button>` element inside `#filter-container`, absolutely positioned at the right edge of the input.

**Visibility:** Hidden by default. Shown when `#filter-input` value is non-empty.

**Accessible implementation:**
- `aria-label="Clear filter"` on the button
- `type="button"` to prevent form submission
- Keyboard reachable via Tab (comes after the input in DOM order)
- On click: clears filter input value, calls `clearFilter()`, returns focus to the filter input

**`clearFilter()` function:**
1. `_filterQuery = ''`
2. `filterInputEl.value = ''`
3. Hide clear button
4. Remove all `hidden` attributes from `.item-row` and `.group-section` elements
5. Restore collapsed group state from `collapsedGroups`
6. Restore plain `textContent` on all `.item-title` and `.item-url` elements (remove `<mark>` tags)
7. Restore original group header count badges
8. Hide `#filter-empty-state`, show `#item-list`

## 10. Event Handling

**Three new event listeners**, all attached to specific elements (not delegated to `document`):

| Event | Target | Handler |
|-------|--------|---------|
| `input` | `#filter-input` | Debounced: clear timer, set new 150ms timer, toggle clear button visibility |
| `click` | `#filter-clear-btn` | Call `clearFilter()`, focus `#filter-input` |
| `keydown` | `#filter-input` | If `Escape`: call `clearFilter()`, keep focus on input (AC8) |

**Why not delegated:** These events are scoped to two specific elements. Adding them to the existing `document.addEventListener('click')` would add branching to an already-complex handler. Separate listeners are cleaner.

**Interaction with existing Escape handler:** The existing `document.addEventListener('keydown')` handler checks for Escape to close dialogs. The filter input's `keydown` handler fires first (more specific target). It should call `e.stopPropagation()` when the filter is non-empty to prevent the Escape from also hitting the dialog-close handler. When the filter IS empty, Escape on the input is a no-op (does not propagate either, since there is nothing to clear).

## 12. Non-Goals

- **Fuzzy search** — owned by B-052; B-021 uses simple substring matching only
- **Persistence of filter** — filter is cleared when panel closes/reopens (panel-lifetime state only)
- **Filter by group** — not in scope; the filter matches against title and URL only
- **Filter by live-state** — filtering by "live", "audible", "drifted" status is not in scope
- **Filter in newtab or popup** — sidepanel only

## 14. Risk Assessment

| Risk | Severity | Mitigation |
|------|----------|------------|
| Filter + live-state patch race | LOW | `refetchAndPatchLiveState()` patches `data-*` attributes on existing rows. If a row is `hidden` by the filter, the patch still applies (hidden DOM nodes retain attributes). No conflict. |
| Filter + broadcast re-render race | LOW | When `renderAll()` is called from a broadcast, it rebuilds the DOM and then re-applies the active filter. The cache is updated first, so the filter always operates on fresh data. |
| Highlighting XSS | NONE | `buildHighlightedText()` uses `document.createTextNode()` for all user data and `<mark>` element creation — never `innerHTML`. |
| Performance on 500 items | LOW | `applyFilter()` is a single DOM walk with `hidden` attribute toggling. O(n) with n = item count. No DOM creation, no layout thrash. Well under 16ms budget. |

## 15. Interaction with Collapsed Groups

When a filter is active and a group has matches inside it:

1. The group section is shown
2. The `.group-items` container is forced visible (ignoring `collapsedGroups`)
3. Only matching item rows are visible; non-matching rows are hidden

When the filter is cleared:

1. All item rows become visible
2. Collapsed state is re-applied from `collapsedGroups` set
3. Group header `aria-expanded` attributes are restored to match `collapsedGroups`

This ensures the user sees all matches regardless of collapse state, and clearing the filter returns to the pre-filter visual state.
